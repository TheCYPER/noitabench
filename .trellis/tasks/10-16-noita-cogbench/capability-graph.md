# 能力图、遭遇点和综合分（v2）

> 2026-10-21 按你的反馈重写。v1 的“24 个微任务 + 组合任务 + 完整对局”作废，换成：
> - 整个游戏是一个开放的冒险世界，没有一个个独立的任务关卡；
> - 原来的微任务变成“遭遇点”：带变体的预制地形，由世界生成器散落到地图里，agent 可以去处理，也可以绕开；
> - 评测是隐性的：agent 不知道自己在被测，系统提示里只有游戏说明；
> - 每局结束给一个综合分，由各项能力的评测汇总而来。
> 世界怎么生成见 `world-design.md`；时间模型见 `tick-design.md`。
> 2026-10-26 按第二轮问卷更新：游戏目标改为“尽量往下走”（Q9）；元认知只看行为，取消押注祭坛（Q7）；综合分 = 80% 能力分 + 20% 深度分（Q6、追问）；遭遇点清单已确认（Q10）。

## 1. 隐性评测的原则

| 原则 | 具体做法 |
|---|---|
| 不提“测试” | 系统提示只说明这是一个游戏、怎么操作、游戏目标是什么（尽量往下走）。不出现“能力”“评测”“任务”这类词 |
| 没有题目 | 不给任何遭遇点单独的目标说明；遭遇点看起来就是地图的一部分 |
| 不强制提问 | 取消 v1 里“强制回答 5 个预测问题”的设计；元认知只从行为推断（第 4 节 N10） |
| 评分不可见 | agent 能看到的只有游戏内的东西（血、金币、深度）。综合分和各项能力分只在局外计算 |
| 遭遇点不扎堆 | 同一类遭遇点之间隔开，变体按种子随机，避免 agent 认出“这又是那个关卡” |

## 3. 遭遇点

### 3.1 遭遇点是什么

遭遇点就是 Noita 里的“预制场景”（pixel scene）：一张小图（最大 256×256 像素），画好地形、液体和物品摆放，生成地图时放进某个群系。每个遭遇点有：

- **变体参数**：哪些格子换成哪种液体、放哪只敌人、瓶子里装什么。变体按种子抽，也受扰动规则影响。
- **触发区**：agent 进入这个区域，就算“遇到了”这个遭遇点，开始记录。
- **评估函数**：读这一段的事件日志，给相关能力节点打分。agent 没进触发区，这个遭遇点就不计分（不算 0 分）。
- **必经或可选**：必经的放在主路径上（比如横跨整层的岩浆河），绕不开；可选的放在侧面群系或岔路里，通常有奖励（法术、瓶子、金币）。

### 3.2.1 陷阱

第 2 周做遭遇点时，优先用 `cp1-feedback.md` 第 3.1 节的陷阱（岩浆薄壳、火药夹层、可燃气囊、酸桶走廊、悬沙、诱饵、连锁）。每个陷阱都要留下能察觉的线索，否则测的是运气。

### 3.3 每局的测量机会

每局地图按种子生成，但生成器保证：
- 每层主路上至少 2 个必经遭遇点（全局共 6 个以上）。必经场景所在的通道用砖围住，初始挖掘杖挖不穿，所以绕不开（CP2 决定，2026-10-27；之前用岩石时 13 到 30 格就能挖过去）。第一版的必经集合：第 1 层 E16、E08；第 2 层 E07、E23、E22；第 3 层 E02、E23、E12；封印前 E06（2026-10-26 由世界生成原型定下，写在 `content/biome_map.json`）；
- 每个基础节点在整张图上至少有 3 个遭遇点（含可选）；
- 同一类遭遇点在一张图里最多出现 2 次。

agent 实际遇到了多少，取决于它走哪条路、活多久。每项能力分都附带“遇到了几次”，次数太少的能力分只作参考，不进综合分（第 5.2 节）。

## 4. 每项能力怎么评

每项能力由两部分组成：遭遇点评估（第 3.2 节的“看什么”）和全局指标（整局都在算，不依赖遭遇点）。

| 节点 | 全局指标（整局都在算） |
|---|---|
| N1 | 同一种危险“第一次吃亏之后”再次吃亏的比例 |
| N2 | 局内：前面观察到的规则后面用没用上。跨局：同类遭遇点在后几局的表现提升；工作区笔记被检索并用上的次数；笔记里被后续观察推翻的条目是否更正 |
| N3 | 是否在需要之前拿到关键物品；回头路长度；每层用的决策数 |
| N4 | 第一次遇到某种通用物理情况（积水、火往上烧、轻的浮起）时的处理是否合理 |
| N5 | 实际路线长度和最短可行路线的比；射击命中率 |
| N6 | 对新材料、新物品做试验的比例；试验的信息量（试完是否改变了行为） |
| N7 | 进入危险前是否 `inspect`；`inspect` 的结果后来是否用上 |
| N8 | 每次改法杖后，法杖的伤害或通过能力是否提升；组出的法杖是否解决了当时的问题 |
| N9 | 每个风险选择按事后可算的期望值打分：冒险成功不一定加分，冒不必要的险扣分 |
| N10 | 在不确定的场合“先试再做”的比例；不确定时是否收手或绕开；死前是否已经有足够的信号却没有收手 |
| C1–C3 | 对应组合场景（整层的资源、陌生群系、破封）的完成度；失败时按检查点归因到基础节点 |
| C4 | 同一规则种子族里，第 2、3 局相对第 1 局的进步（深度、受伤、决策效率） |

**元认知只看行为（Q7）。** 第一版不加押注祭坛，也不让 agent 声明把握程度，所以“判断准不准”（校准）这一侧面不测。以后如果要测，可以离线分析 agent 的思考文字，不影响它的行为。

## 5. 综合分

### 5.1 每项能力的分数

每项能力分在 0 到 100 之间：
1. 每次遇到相关遭遇点，评估函数给出 0 到 1 的分数；
2. 全局指标归一化到 0 到 1；
3. 两者按“遇到的次数”加权平均，乘以 100。

### 5.2 一局的综合分

已定（Q6、追问）：**综合分 = 80% × 能力分 + 20% × 深度分。**
- 能力分 = 11 项能力分（N1–N10 和组合能力 C）的等权平均，C 取 C1–C4 的平均；
- 深度分 = 这一局到达的最深位置占整张图深度的比例 × 100。

- ~~某项能力这一局遇到的机会少于 2 次：不进综合分，其余项重新等分权重~~（2026-10-28 改：这样会奖励“早早结束、少做事”，截到第 800 帧的 bot 得 84.2 分，比走到第 2 层的 80.8 还高）。现在：每项能力分乘以 n / (n + 2)（n = 这一局遇到这项能力的机会数，没遇到算 0），11 项等权平均后作为能力分；报告里仍注明机会数少于 2 的“覆盖不足”。
- 深度分只算到封印为止，除非玩家真的进了封印房间（2026-10-28：防止在封印旁边挖到地图底部）。
- 综合分和每项能力分一起报告：综合分是标题数字，能力画像是它的拆解。
- 一个模型的最终成绩：所有局综合分的平均和置信区间。
- 人类基线用同一套评估，得到人类的综合分和画像。

## 6. 消融

| 消融 | 怎么做 | 测什么 |
|---|---|---|
| 扰动强度 0 对比 1 | 同一模型分别跑原版规则和扰动规则的种子族 | 参数记忆 |
| 跨局记忆开关 | 工作区跨局保留，或每局清空 | 外部记忆 |
| 最小 harness 对比自建 harness | 只给游戏工具，或给全部 harness 能力（`design.md` 第 6 节） | harness 设计能力对成绩的贡献 |
| 观测：截图 | 加上截图观测 | 像素和结构化观测的差别 |
| 可回滚 | 允许有限次回到之前的存档 | 能反悔时的行为变化 |
