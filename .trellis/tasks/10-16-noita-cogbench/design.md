## 1. 总体结构

```
noita-cogbench/
├── crates/
│   ├── sim/        Rust：像素网格、材料、反应、火、爆炸、液体气体运动
│   ├── game/       Rust：玩家、敌人、物品、法杖法术、魔药、扰动、世界生成、存档、事件日志、指令和打断、观测渲染
│   └── py/         Rust → Python 绑定（PyO3 + maturin），对外只暴露 Env
├── python/noitabench/
│   ├── env.py          Env：reset / command / observe / snapshot / restore / inspect
│   ├── obs/            三种观测的格式化
│   ├── harness/        agent 运行时：模型适配、工具注册、工作区、Code Mode、钩子、子 agent、插件、离线库、预算（第 6、7 节）
│   ├── protocol/       JSON Lines 协议和 MCP 工具包装
│   ├── eval/           遭遇点评估函数、全局指标、综合分（capability-graph.md）
│   ├── server/         给网页用的 WebSocket 服务：人类游玩、回放
│   └── worldtools/     拼块模板生成、世界预览图
├── content/        materials.json、reactions.json、spells.json、enemies.json、potions.json、biome_map、群系定义、拼块模板、遭遇点预制场景
└── web/            静态网页：人类游玩界面、回放、并排对比、画像报告（共用一个渲染器）
```

原则不变：游戏规则只在 Rust 里；你审查的入口是 Python 测试、世界预览图和网页回放；单线程、可复现。

- **物品**：瓶子（装、倒、喝、扔）、法杖、法术、桶（火药桶、酸桶、油桶，可被打破，见 `cp1-feedback.md` 第 1 节）、可踢。所有物品都是简单弹道物体：有重力、会弹跳、不翻滚，不做刚体（Q16）。
- **敌人**：哈米斯（近战扑击）、霰弹希西（远程）、斯滕达里（吐火球，免疫火）。数值取自 `enemies.json`，速度和攻击间隔按 tick 大小调。

## 4. 防污染扰动

同 v1：
- 规则种子决定扰动后的反应表和魔药配方；同一个规则种子族里，地图每局不同、规则不变。
- 强度 0 = 原版；强度 1 = 在族的层面重新抽产物和概率；强度 2 = 再让 1 到 2 个材料“不合群”。
- 约束：表封闭（产物都在材料清单里）；每个遭遇点在扰动后仍然有解（`world-design.md` 2.5 节）。
- 只扰动反应表和配方；名称、外观、属性、法术、敌人不动。
- agent 拿不到任何外部资源。

## 5. Agent 接口

### 5.1 时间和指令

见 `tick-design.md`。采用方案 B（Q1）：tick 固定 10 帧（Q2）；指令可以持续多个 tick，直到完成、被打断或满 5 秒；世界在 agent 思考时暂停。

### 5.2 观测

| 模式 | 内容 |
|---|---|
| 结构化文本 | 状态（血、法力、位置、状态效果、悬浮剩余）、附近实体、法杖和背包、停下来的原因、期间事件摘要、游戏目标 |
| ASCII 地图 | 以玩家为中心，每字符 4×4 像素，默认 64×32 字符，带图例 |
| 截图 | 以玩家为中心 256×192 像素 |

图例只写材料名称，不写性质。

### 5.3 查询

`inspect(坐标 / 物品 / 实体)`：返回精确材料、瓶子内容、物品数值、实体血量和状态；不返回材料所属的族。不推进游戏时间，但算一次决策（Q18）。

### 5.4 不再有“预测”动作

v1 的 `predict` 动作会让 agent 察觉到在被测，取消。元认知只看行为指标（Q7），不加押注祭坛之类的游戏内机制。见 `capability-graph.md` 第 4 节。

### 5.5 接入方式

- JSON Lines 协议（`reset`、`command`、`observe`、`snapshot`、`restore`、`close`）。
- MCP 工具包装：外部 agent 框架（DeepSeek Harness、Claude Code、Codex 等）可以直接把游戏当成一组工具来玩。作为额外赛道放到第二阶段（Q5）。
- 我们自己的 harness（第 6 节）是主赛道。

## 6. 自建 harness（参考 DeepSeek Harness）

### 6.1 DeepSeek Harness 的底层设计（调研）

DeepSeek Harness（`dsh`）是 DeepSeek 在 2026 年 8 月开源的 agent 运行时，MIT 许可，开发者预览阶段。和我们相关的设计：

| 设计 | 内容 |
|---|---|
| 一切皆插件 | 运行时由插件按配置组装；工具、提示片段、监听器都按 agent 隔离注册 |
| 事件总线和钩子 | 每次工具调用经过“执行前 → 执行 → 执行后 → 结果”几个阶段，插件可以在执行前放行或拦截、执行后改写结果 |
| Code Mode | 模型不只是一次调一个工具，而是写一段程序（TypeScript 或 Python），在程序里循环、判断、并发地调用工具。运行时会为模型生成一份带类型的工具 SDK |
| 子 agent | 父 agent 可以派生子 agent：全新上下文的“spawn”，或继承父 agent 已完成对话的“fork”；一次性或可继续对话；可限制子 agent 能用的工具、递归深度、模型和人设 |
| 会话日志 | 只追加的事件日志，支持从某一点分叉出新的会话 |
| 其他 | 技能、自动记忆、工作流、实验性的 agent 团队 |

来源：GitHub `deepseek-ai/deepseek-harness`（README）、DeepWiki 对其 Agent System、Subagent Orchestration、Tool Registry 的说明。

### 6.2 我们给 agent 的 harness 能力

我们自己实现一个精简的 Python 版本，借用上面的概念，分六层。agent 在游戏开始时就有全部能力，怎么用、要不要改，由它自己决定：

| 层 | 能力 | 例子 |
|---|---|---|
| L0 游戏工具 | `tick-design.md` 第 4.3 节的全部指令、`inspect` | `walk_to(x=180)` |
| L1 工作区 | 一个跨局保留的文件夹，读、写、搜索、改。两个配额：笔记和技能说明合计约 8,000 字符（Q19，用来测记忆管理）；插件和脚本另给约 64,000 字符（追问） | `notes/化学.md`、`skills/过岩浆河.md` |
| L2 Code Mode | `run_code(python)`：在沙箱里跑 agent 写的 Python，可以循环调用游戏指令、读观测。每次最多执行 200 个游戏指令、CPU 时间有上限、不能联网、只能读写工作区 | “一直往下挖，碰到岩浆或血低于 30% 就停” |
| L3 钩子 | 订阅事件并自动执行脚本或打断：受伤、看到新材料、血量低于某值、进入液体…… | “看到没见过的材料就自动 `inspect`” |
| L4 子 agent | `spawn_agent`（全新上下文）/ `fork_agent`（继承当前对话）：选人设、可用工具、模型（限定在同一家的可选型号里）、一次性或可继续 | 派一个子 agent 专门整理笔记，或专门在试验场里设计法杖 |
| L5 改 harness 本身 | 写插件：注册新工具、新钩子，改自己的提示片段和上下文整理方式；从离线白名单里安装 Python 库，在插件里使用（Q4 备注、追问） | 写一个“液体图鉴”插件自动整理见过的反应；装 networkx 做路线规划 |

**L5 的边界。** agent 可以改的是“它自己怎么思考、怎么记、怎么调用工具”；不能改的是游戏和裁判：
- 不能改游戏引擎、评分代码、预算计数；
- 插件只能通过 L0 的游戏工具读世界，拿不到观测之外的隐藏状态；
- 不能联网。库只能从一个离线白名单安装：预先下载好的通用库（如 numpy、scipy、networkx、sympy、pandas），每个模型拿到的白名单一样，装了什么记进事件日志；
- 插件代码在沙箱里运行，CPU 时间和内存有上限。

另外提供一个**法杖试验场**：不进世界、只跑施法算法的模拟器，告诉 agent 某把法杖每秒打出什么。它很便宜，子 agent 可以在里面反复试。

### 6.3 预算

所有 agent（主 agent 和全部子 agent）的模型调用，都算进这一局的预算。agent 能随时查看剩余预算（这对一个 agent 平台来说很正常，不会让它觉得在被测）。Code Mode 和钩子不调模型，不花预算，但受执行时间限制。

### 6.4 对照

| 设置 | 内容 | 用途 |
|---|---|---|
| 自建（默认，Q4） | L0–L5 全开 | 主成绩 |
| 最小 | 只有 L0 和 L1 | 对照：自建 harness 给成绩带来多少 |

## 7. 多 agent 怎么落地

你举的例子是“一个 agent 往那边走，另一个往这边走”。游戏里只有一个角色，所以要先定多个 agent 怎么分工：

| 方案 | 做法 | 好处 | 问题 |
|---|---|---|---|
| a 分叉侦察 | 子 agent 拿到一份**世界快照的副本**，在副本里往某个方向探路，回来汇报；主世界不动 | 就是你说的“分头走”；不用改游戏 | 相当于能预知未来，削弱“不可逆”和风险决策的测量；要限制次数 |
| b 多个角色 | 世界里放 2 到 3 个玩家角色，各由一个 agent 控制，真的分头走 | 最直接；多 agent 协作本身成了一项能力 | 游戏规则要大改；人类基线要多人或一人控多角色；第一阶段做不完 |
| c 只分工思考 | 同一时间只有一个 agent 能控制角色（控制权可以交接）；其他子 agent 只做规划、整理记忆、在试验场设计法杖 | 实现简单；保持不可逆 | 做不到真正的“分头走” |

已定（Q3）：**默认 c，a 作为有次数限制的消融**（每局最多 3 次分叉，每次最多 300 帧）。按 4 周精简排期（Q20），a 在第二阶段实现；b 第二阶段再看。

## 8. 人类基线

| 方面 | 做法 |
|---|---|
| 界面 | 网页游戏界面，和回放共用一个渲染器；本机的 Python 服务通过 WebSocket 跑同一个 Env |
| 时间 | 和 agent 一样的方案 B：决策点暂停等人操作，被同样的事件打断（`tick-design.md` 4.6 节） |
| 操作 | 键盘和鼠标映射到同一套指令：方向键 = `move`，点地面 = `walk_to`，点敌人 = 瞄准并施法，鼠标悬停 = `inspect` |
| 记忆 | 有一个笔记面板，就是同一个工作区，跨局保留；没有 Code Mode、钩子和子 agent |
| 观测 | 人看渲染画面加 HUD；agent 默认看文本和 ASCII。所以截图消融的结果也拿来和人类对比 |
| 评分 | 同一套评估函数和综合分 |
| 参考模式 | 另有不暂停的实时模式，只作参考，不和 agent 直接比（Q11）；第二阶段实现 |
| 被试 | 两组：玩过 Noita 的和没玩过的，各 4 到 6 人（Q12）。玩过 Noita 的人类对应“有参数记忆”的模型，可以对照扰动的影响 |

## 9. 跨局记忆

- 一个规则种子族包含多局：死后重置，地图重新生成，规则不变。
- 跨局保留的只有工作区（第 6.2 节 L1）。最小 harness 设置下，工作区就是一个笔记本。
- 三种记忆分开测：参数记忆（扰动强度 0 对比 1）；上下文记忆（同一局内前面看到的规则后面用没用上）；外部记忆（工作区跨局保留对比每局清空）。

## 10. 评测和综合分

见 `capability-graph.md`：开放世界里的遭遇点评估 + 全局指标 → 11 项能力分 → 每局一个综合分。

**综合分 = 80% × 11 项能力分的平均 + 20% × 深度分**（Q6、追问）。深度分 = 这一局到达的最深位置占整张图深度的比例。综合分和能力画像都不给 agent 看。

## 11. 引擎支撑

| 功能 | 做法 |
|---|---|
| 无界面运行 | Rust 核心没有图形依赖 |
| 可复现 | 单线程；随机数来自种子和帧号的哈希；“种子 + 指令序列”完整复现一局 |
| 存档和回滚 | 整个世界状态序列化；研究者做反事实分析；也支撑分叉侦察和可回滚消融 |
| 事件日志 | 每帧的事件 + 每个决策点（帧号、停下原因、指令）+ harness 事件（脚本、钩子、子 agent、工作区读写） |
| 可变速 | 无界面时尽量快跑；网页回放可调速 |

## 12. 预算

按中档模型每步约 1.5 美分估，50 美元约 3,300 次模型调用。开放世界下的默认规模：**1 个规则种子族 × 3 局，每局最多约 1,000 次调用**（主 agent 和子 agent 合计）。在方案 B 下，1,000 次决策大约能走完整张图。

消融（扰动强度 0、最小 harness、截图、可回滚、分叉侦察）另外付费，建议先在便宜的模型上跑。

## 15. 风险

| 风险 | 应对 |
|---|---|
| 开放世界里测量机会不稳定 | 必经遭遇点保底；每项能力报告覆盖次数；能力分按机会数打折（× n/(n+2)，2026-10-28 改，原来“覆盖不足不进综合分”会奖励早早结束） |
| 遭遇点被 agent 认出“是测试” | 变体按种子随机、同类不扎堆、不给单独目标；定期抽查 agent 的思考记录里有没有“这是测试”之类的说法 |
| 扰动后遭遇点不可解 | 生成后检查，不过就换种子 |
| 自建 harness 让成本失控 | 所有子 agent 计入同一预算；Code Mode 限制每次指令数和执行时间 |
| 分叉侦察削弱风险测量 | 默认关闭，只作消融，并限次数 |
| 范围比 v1 大很多 | 采用 4 周精简排期（Q20），部分内容放第二阶段，见 `implement.md` |
| AI 写的 Rust 你没法审 | 世界预览图、网页回放和 Python 测试是审查入口 |
