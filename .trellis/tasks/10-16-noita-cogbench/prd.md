## 1. 目标

做一个 Noita 风格的开放冒险游戏：落沙物理沙盒、精简的可组合法杖、层层往下的程序生成世界。它是**评测 LLM agent 认知能力画像**的环境，但对 agent 来说它只是一个游戏，agent 不知道自己在被测。每局结束给一个综合分，并拆解成各项能力的画像；同一套评分也用在人类玩家身上，作为基线。

最终交付三样东西（B1）：评测环境、公开的 benchmark、一篇论文。第一阶段 4 周做通核心闭环（Q20）；公开发布和论文规模的实验放到第二阶段。

| 决策 | 来源 |
|---|---|
| 主成绩用自建 harness，六层能力全开：游戏工具、工作区、Code Mode、钩子、子 agent、改 harness 本身；最小 harness（只有游戏工具和工作区）作对照 | I4、审阅 2、Q4 |

### 2.4 能力画像和评分
| 决策 | 来源 |

## 5. 验收标准（第一阶段）

- [ ] AC1（R15）Python 里能直接导入环境，无界面跑完一局；一条命令能用脚本 agent 跑完一局。
- [ ] AC2（R15）同一个种子加同一串指令，两次运行的最终状态和事件日志完全一致；存档后恢复再重放也一致。
- [ ] AC3（R1–R4）材料、反应（含灭火）、法术、魔药、敌人、拾取、踢、状态都实现，每一项至少被一个测试或遭遇点用到。
- [ ] AC4（R5，CP2 改）反应表在所有种子里都等于原版；不同种子的秘方配方不同，每种 3 种配料；agent 没有任何联网或查资料的途径。
- [ ] AC5（R6–R7）时间模型 B 按 `tick-design.md` 实现：tick 10 帧、单条指令最长 300 帧、默认打断四条；停下原因和期间事件写进观测和事件日志；`inspect` 计入决策数。
- [ ] AC6（R8）任意种子生成的世界都通过生成后检查；世界预览图能看出 3 层、左右不同群系、主路和遭遇点；你在检查点上认可“像 Noita”。
- [ ] AC7（R9–R10）第一阶段实现至少 12 个遭遇点（每个基础节点至少 1 个，加上全部必经遭遇点）；每局输出综合分、11 项能力分、深度分和每项的覆盖次数；评分不出现在 agent 的任何观测和工具输出里。
- [ ] AC8（R11）同一规则种子族下多局：地图不同、规则相同；工作区跨局保留；对照组每局清空。
- [ ] AC9（R12）agent 能用六层 harness 能力：写插件给自己加工具、从离线白名单装库、派生子 agent；两个配额生效；所有模型调用计入预算；改不了引擎、评分和预算；最小 harness 可切换。
- [ ] AC10（R13）四家模型都能跑；每局记录 token 和美元；在参考模型上实测跑完默认规模不超过 50 美元。
- [ ] AC11（R14）人类能在网页里用暂停模式玩完一局，录像格式和 agent 一致，得到同样的综合分和画像。
- [ ] AC12（R16）网页能回放、调速、并排对比、显示报告和世界预览；网页里没有游戏逻辑。
- [ ] AC13（审阅 4）抽查一批 agent 的思考记录，没有明显把游戏当成“测试”或认出遭遇点是“关卡”的说法。

## 6. 不在范围内

第二阶段：剩下的 12 个遭遇点；分叉侦察消融；实时人类模式；外部 harness 赛道（MCP）；群系修饰；商店、天赋、宝箱；人类被试正式招募和全量试跑；公开发布和论文实验；英文版文档。

整个项目都不做：RL；agent 联网或访问外部资源；能力 11、12（第一版）；判断校准的直接测量（押注、强制预测）；多个玩家角色（第二阶段再评估）；多线程逐位一致和状态哈希；扰动名称、外观、属性、法术、敌人；刚体物理；音效；全部 466 种材料和 422 个法术；Noita 那么大的世界、平行世界和隐藏区域。

## 7. 风险

- **4 周很紧。** 人类界面、可自改的 harness、Noita 式世界生成都在里面。已把 12 个遭遇点、分叉侦察、实时人类模式等放到第二阶段；每周有检查点，进度不对就再砍。
- **开放世界的测量不稳定。** 必经遭遇点保底；报告覆盖次数。
- **隐性评测可能被看穿。** 抽查思考记录（AC13）。
- **自改 harness 的安全和成本。** 插件在沙箱里跑，只能通过游戏工具读世界；离线白名单统一；子 agent 计入同一预算。
- **预算。** 50 美元大约是 3 局、每局约 1,000 次模型调用。
- **你不看 Rust。** 审查入口是世界预览图、网页回放和 Python 测试。
