# Architecture design — NoitaClone

Parent-level technical design, revised 2026-10-07 against `research/design-review.md`. Children refine their own
`design.md` against it. **Normative detail lives in the knowledge base (KB) `.trellis/spec/game-design/`**: this file
cites rule IDs (`SIM-R22`, `WAND-R40`, ...) instead of restating them, and where it disagrees with a KB page the page
wins. "(default; pending user decision DN-xxx)" marks the recommended default of `decisions-needed.md`; nothing so
marked is decided. Units (KB index §1): time = integer frames at 60 Hz (never seconds); length = cell px, y grows
down; speeds px/s in data; angles degrees; HP and damage are **internal in code, x25 only when displayed** (SPELL-R03).

reads `World` and `Game` directly (5.1); it does not go through the bench observation path.

### 1.1 Runtime data and the content hash
- `research/*.json` are provenance and contain prose, palettes and wiki text; the runtime files are **generated** by
  `scripts/build_runtime_data.py` with prose removed, so a wording edit cannot change `content_hash` (VER-R03).
- Files: `materials.json` (all 466 rows, `u16` id = rank by `xml_order`, `air` = 0; MAT-R01), `reactions.json` (the 330 `xml_`
  rows; MVP compiles the 39 of MVP-R02), `tags_index.json`, `spells.json` (422 rows keyed by `game_id`; SPELL-R01, R10),
  `wand_templates.json`, `player.json`, `enemies.json`, `tasks/*.json`. Loaders never re-apply defaults (MAT-R04, G11).
- Loader asserts: 466 materials / 330 reactions / 79 tag keys / 422 spells; the kind counts of SIM-R04; bound ids `air, fire,
  smoke, water` present (MAT-R02); unknown ids or tags fail the load (RXN-R18). Material set: load all 466, MVP-40 is the enabled
  content, 39 reactions compiled (default; pending user decision DN-MAT-02; set itself DN-MAT-01).
- `content_hash = blake3(canonical runtime data + per-spell `implemented` bits + task generators)` (VER-R03).

## 2. Simulation core (KB: pixel-simulation.md, materials-reactions.md)

### 2.1 Grid and cell
- `World { w, h, tiles: Vec<Tile>, chunks: Vec<ChunkMeta>, frame: u64, seed, cell_seed, active: Rect }`; w and h are
  multiples of 64 (SIM-R01). Simulation chunk 64x64 is the scheduling unit, storage tile 32x32 (SIM-R02, SIM-R24).
  Reads outside the world return the indestructible `boundary` material; out-of-world writes are ignored.
- `#[repr(C)] Cell { mat: u16, life: u8, burn: u8, var: u8, flags: u8 }`, exactly 6 bytes, no padding (SIM-R03; default; pending
  user decision DN-SIM-05). flags: `UPDATED`, `BURNING`, `DIR`, `OBJECT` (reserved, SIM-R86). No velocity, temperature,
  wetness, parity bit or settle counter. `var` is cosmetic and comes from a stateless hash (SIM-R76).
- Timers: `life`/`burn` count per-material units (`life_unit`, `burn_unit`), exact for all 15 lifetimes (SIM-R35; default;
  pending user decision DN-SIM-02). Rationale: lifetimes reach 1,350 frames and fuel 1,000,000, `u8` holds 255.
- Kinds are derived once (Air, Static, Powder, Liquid, Gas, Fire, Solid; SIM-R04). The 132 Solid materials map to Static (SIM-R85).
- Integer ingestion (SIM-R05): every float becomes an integer at load; densities `x10000` as `u32` (default; pending user
  decision DN-SIM-06). A per-material `MotionParams` table (`fall_int`, `fall_frac_q8`, `slide_p`, `lateral_L`, `gas_act`,
  `life_unit`, `burn_unit`, `reactive`, ...) is computed at load; no float is read inside a per-cell rule. Parameter
  mappings (SIM-R31/R32, DN-SIM-11) are [CAL] values kept in the table or `sim::consts`, never inline.

### 2.2 Dirty rects and sleeping
- One dirty rect per chunk (SIM-R10). A write at `p` makes `dirty(f+1)` contain `[p-WAKE, p+WAKE]` with `WAKE = 12`
  (SIM-R11; a 1-cell halo is wrong for liquids that hop up to 10). A visit that leaves a cell unchanged but able to change
  (running timer, BURNING, failed probabilistic roll, adjacent reaction partner) calls `keep_awake()` (SIM-R12).
- A task never mutates another chunk's metadata: it returns write boxes task-locally; a serial merge in ascending chunk index
  dilates, clips and unions them after each pass (SIM-R13, SIM-R26, SIM-R74). End of frame: `dirty = next`.
- `UPDATED` is raised by `set`/`swap`, gates visits only, is cleared at frame end, is never serialised or hashed
  (SIM-R15). Parity bits and generation stamps are forbidden (they stall cells under dirty rects).
- Only chunks intersecting the chunk-aligned `active` rect run; writes into frozen chunks are dropped as `boundary`
  (SIM-R14; default; pending user decision DN-SIM-04). Game world 2048x1536 uses a 512x512 active rect around the player;
  benchmark worlds are fully active (default; pending user decision DN-SIM-07).
- Transparency invariant: identical state with dirty rects on, off, and after a snapshot restore into all-dirty (SIM-R72).
  The 6 `air`-input reaction rows of MVP-40 keep exposed surfaces awake; accepted for MVP-40 (default; pending DN-SIM-09).

### 2.3 Scheduling and parallelism
- Four passes over chunk class `(cx&1, cy&1)`, order rotated by `frame mod 4`; rows bottom-up; column direction
  `(frame+cx+cy)&1`; both pure functions of the frame (SIM-R20, R21, R73). Same-class windows are 64 cells apart.
- Reach: `MAX_REACH = 32 = CHUNK/2` (window 128x128, compile-time assert `2*MAX_REACH <= CHUNK`), rule authors stay within
  `RULE_REACH = 16`, debug builds assert every `get/set` offset and track the maximum (SIM-R22, R23, R77).
- Storage and threads: `Vec<Tile>` split into disjoint windows with `iter_mut` then rayon `par_iter_mut`; safe Rust, no
  `SyncGridPtr`. A flat array behind one documented `unsafe` wrapper is the fallback only if profiling shows the tile
  indirection costs > 10% (SIM-R24). `parallel` cargo feature (default on); the single-thread path is the same code.
- Rules touch the world only through the rule API `get/set/swap/mat/rand/keep_awake/emit_particle/request_explosion`
  (SIM-R25), so each rule is unit-testable on a 5x5 patch.

### 2.4 RNG
- Cell randomness is a stateless hash `mix64(cell_seed ^ frame*K1 ^ pass*K2 ^ world_index*K3)` (SIM-R70; default; pending user
  decision DN-SIM-01). No shared mutable RNG, no per-chunk stream, no `HashMap` iteration in `step` (SIM-R74, DET-R05).
- Other streams (`worldgen`, `spells`, `ai`, `spawn`) are separate seeded PCG/xoshiro streams derived by DET-R04, so an extra draw in
  one cannot change another (tested). Spells, shuffle and worldgen never use frame-number seeds (SPELL-R43).

### 2.5 Per-visit rules
- Visit order: timers, burning, reactions, motion; swaps conserve matter; kind gates motion before density (SIM-R30, MAT-R08).
  Only Air, Gas, Fire and Liquid cells are ever displaced; equal density never swaps vertically.
- Powder and liquid fall use `liquid_gravity`-derived multi-step fall capped at 6, then diagonals; liquids then hop laterally
  up to `L <= 10`; viscosity affects powders only (SIM-R31, R32, R33; default; pending DN-SIM-11). Gas acts with probability
  `gas_speed/100`, up first (SIM-R34; default; pending DN-SIM-03). Static cells never move (SIM-R39).
- Reactions: a dense per-pair table of candidate slices in file order, first success wins; positional outputs; tag inputs
  expanded at load; `reactive` flag per material; roll `below(10000) < round(p*100)`; one random 4-neighbour per reactive
  cell per visit (SIM-R38, RXN-R02..R08, RXN-R17; cadence default; pending user decision DN-MAT-03). 3-input and ReqReaction rows,
  `req_lifetime` and entity-spawning rows are dropped from the MVP (MVP-R03).
- Fire: burning is a **cell state** (`BURNING` + `burn`), not a cell kind; Fire-kind cells (`fire`, `flame`, sparks) are
  ignition sources and emissions that move like gas into Air (SIM-R36, SIM-R37, FIRE-R01..R07; ignition chance and fuel units
  default; pending DN-MAT-05, DN-MAT-06). **Water does not extinguish burning cells**: `[fire]+water` boils the water and
  burning ends by fuel, air starvation or deletion (FIRE-R08). Only entities are extinguished by liquid (DAMAGE-R14).

### 2.6 Thrown matter (particles)
- Cells carry no velocity. A `Particle` (Q16.16 position and velocity, `MAX_PARTICLES` 100,000, serial id-ordered phase after
  the cell passes) exists only for liquid thrown out of explosion craters and fast-entity splashes (SIM-R45..R47; constants default;
  pending user decision DN-SIM-10). Trails and sprays write cells directly (SPELL-R30, SPELL-R46).
- Staging: the first explosion milestone ships a matter-conserving "displace to nearest free cell by a deterministic spiral"
  stop-gap behind the same `explode` API; the particle phase replaces it when thrown-liquid visuals or tasks need it. Whether the
  subsystem ships in the MVP at all is review decision 4 (no global id yet; see plan-summary).

### 2.7 Explosions
- `request_explosion(&ExplosionConfig{radius, ray_energy, max_durability, create_cell{material,prob}, hole_destroy_liquid,
  damage_internal, knockback_force}, x, y, source_id)`; configs come from the MR "Explosion/digger sources" table, never from
  the incomplete `spells.json` configs (SIM-R51; DF-3).
- Ray model: rays spend `ray_energy` on each cell's `hp`, a cell is removed only if `durability <= max_durability_to_destroy`,
  fire (or `create_cell`) appears with `create_cell_probability` on every destroyed cell, destroyed liquid is thrown unless
  `hole_destroy_liquid` (SIM-R50..R52, DUR-R01..R03; default; pending user decisions DN-SPELL-04, DN-MAT-07). No loose-ground
  collapse (SIM-R52, SPELL-R35). The disc/`power*(1-d/r)` model of the first draft is superseded.
- Serial phase with a queue, caps 32 explosions and sum(R^2) <= 400,000 per frame, chain reactions deferred a frame
  (SIM-R54; default; pending DN-SIM-12). Returns bbox, destroyed-material histogram and entities in radius (SIM-R53).
- Entity effects: flat damage inside the radius (falloff UNVERIFIED, DN-SPELL-10), knockback falling off with distance
  (DAMAGE-R12), damage floor by radius (DUR-R08, SPELL-R33), player explosion multiplier 0.35 (DAMAGE-R06).

### 2.8 Queries
- `Grid::blocked(mask)` over the kind bitmask with the four Noita ray presets (SIM-R60); `raycast`, `material_at`, `set_cell`,
  `paint_disc`, `fill_rect`. Entities and projectiles run in a serial phase and are not bound by `MAX_REACH` (SIM-R61).
- Projectile sweep: integer DDA from old to new cell, default world mask Static/Powder/Solid, liquids only if
  `die_on_liquid_collision`; normal from the 7x7 blocked-neighbour sum; bounce and penetration per SIM-R62, SIM-R63.
- Entity boxes sweep column/row-wise with step-up `climb_over_y = 4` px and sub-pixel `f32` positions; player collision box
  4 x 6.6 px, hitbox 6 x 16 px (SIM-R64, SIM-R65; ED Key numbers). Entities are not stamped into the grid (SIM S8).

### 2.9 Frame pipeline, budgets, hashing
- `Game::step` follows SIM-R80: (1) inputs, entity logic, wand timers and casts; (2) `bodies_stamp` hook (empty in MVP); (3) status
  ticks, material contact damage (HAZ-R01..R03) and projectile/entity sweeps, serial in id order; (4) explosion phase;
  (5) four cell passes with serial merge after each; (6) particle phase; (7) `bodies_unstamp`; (8) UPDATED clear, `dirty = next`,
  events, optional hash. Wand mana regeneration and cast-delay/recharge countdowns tick every frame for every wand (WAND-R57).
- Budgets are per named scenario, not one number (SIM-R81, SIM-R82; default; pending DN-SIM-07). Criterion benches record ns per
  active cell for: empty, 5% sand rain, water pour, lava+water, burning oil lake, 10 explosions R30 and one R250, all-active
  soup, 1/2/4/8 threads, dirty rects on vs off. Gates: typical task scene (<= 10% active) at 512x512 reaches >= 300 frames/s end to
  end through `noita_bench` with frame skip 4 (3.33 ms/frame); the all-active worst case and 1024x1024 are report-only until
  measured. Every performance figure in the research is UNVERIFIED because no code existed.
- State hash: bytes per SIM-R75 (cells with `UPDATED` cleared, particles by id, entities with f32 via `to_bits`, wands, task
  state); algorithm blake3 with per-chunk Merkle leaves re-hashed only for chunks written since the last hash, returned on
  every `step`, full-grid hash every 600 frames and at episode end (DET-R02, DET-R03; default; pending DN-SIM-08, DN-BEN-02).
  Snapshot = cells + frame + seed (+ particles, entities); restore rebuilds all-dirty (SIM-R78).

## 3. Spells, wands, entities (KB: wand-casting.md, spells.md, entities-damage.md)

### 3.1 Units and data
- `Hp`/`Damage` newtype holds the internal XML-unit value; x25 only in observations, UI and test boundaries; constants carry
  `_internal` or `_display` suffixes; `spells.json` `damage*` fields are display values and are converted once at load
  (SPELL-R03; default; pending user decision DN-SPELL-02). Target dummy HP = 4.0 internal (100 displayed).
- Spell scope ladder: all 422 parse and validate; MVP-50 first (35 D0, 6 D1, 9 D2; SPELL-R45), then all D0 (127), then D1 by
  feature, then roughly 60 D2 (default; pending user decision DN-SPELL-01). All spells unlocked (default; pending DN-SPELL-05).

### 3.2 Spell data model
- `SpellDef { game_id, primitive, projectile: Option<ProjectileSpec>, card: CardDelta, trigger: Option<TriggerSpec>,
  material: Option<MaterialSpec>, features, handler: Option<HandlerId>, implemented }` with the 7 primitives, D0/D1/D2 classes and the D1
  feature library of SPELL-R36..R41 and DF-5. No per-spell enum. D2 spells go through a handler registry; the 143 entity-script D2
  spells are deferred (SPELL-R41). Absent XML attribute means the engine default, never 0 (SPELL-R05).
- The `implemented` set is hashed into `content_hash`; task pools and `edit_wand` accept implemented spells only (others give
  `INVALID_ACTION`); a fuzz test casts every implemented spell once. Runtime schema fields agents may see: DN-SPELL-06.

### 3.3 Casting engine
- `cast(&mut WandState, &SpellRegistry, &CastContext, &mut SpellRng) -> CastOutcome`. Pure: no `World`, unit-testable and usable by a
  world-free damage evaluator (3.5). `CastContext` is a read-only struct built by game code: caster hp and max, gold, entity counts for
  Requirement spells in deterministic id order, the global `IF_HALF` flag (WAND-R85; DN-WAND-03), other wands (stage 2).
- `CastOutcome` = `ShotTree`, cast delay and recharge frames, mana spent, recoil, events; `WandState` carries deck/hand/discard,
  uses, `start_reload`, `reloading`, timers. Rules by ID: piles WAND-R10..R12; draw, skip, wrap WAND-R20..R25; shot state and multicast
  WAND-R30..R34; end of click, recharge, cast delay, mana regeneration WAND-R50..R57; mana and uses WAND-R60..R64; always-cast
  WAND-R70..R72; Divide, Add-Trigger, Refresh WAND-R80..R82, R86.
- **Trigger payloads are drawn and paid at cast time** and stored in the `ShotTree`
  (`Projectile{spec, shot, trigger: Option<Trigger{kind, timer_frames, payload: Box<ShotTree>}>}`); at runtime a projectile only
  releases its pre-built payload on collision, timer or death (WAND-R40..R43, SPELL-R18, SPELL-R19). There is no trigger depth limit;
  the recursion limit of 2 belongs to copy spells (WAND-R80).
- Stage 1 = WAND-R01..R64, R70..R72, R80..R82, R86; stage 2 = Greek letters, Duplication, Requirement, Zeta, random-draw spells (WAND S4).
  Shuffle uses the `spells` stream. Open rule choices: empty-deck recharge DN-WAND-01 (default (a), the wiki behaviour), Unlimited Spells
  not in suite v1 DN-WAND-02, wand generation after the core with hand-made task wands DN-WAND-04 (all default; pending).
- `penetrate_entities` and `on_collision_die` are spell/projectile data, not ShotState fields (SPELL-R25); cast delay and recharge
  clamp on the total, concurrently (WAND-R53..R55).

### 3.4 Projectiles and entities
- `ProjectileSpec` per DF-5: speeds in px/s (divide by 60), lifetime +- random, gravity, air friction, terminal velocity 1000 px/s
  (Lightning excepted), bounces, collision flags, damage by type, explosion config (SPELL-R05, R08, R23..R29). Entity hit is a swept
  segment against the hitbox (a point test tunnels at 30 px/frame); first hit by parameter `t`, ties by entity id; one hit per entity
  unless `penetrate_entities`; the shooter is skipped unless `collide_with_shooter_frames` (DAMAGE-R20). The once-per-entity hit list
  is implemented now because MVP-50 needs it (default; pending user decision DN-ENT-02).
- Bomb and Dynamite are ballistic "rolling" projectiles (gravity, bounce, friction, 180-frame fuse, hit points), not Box2D bodies;
  `OBJECT` flag and `bodies_stamp/unstamp` hooks are kept (SIM-R85..R87; default; pending user decision DN-SPELL-03).
- Damage pipeline order: immunity gate, hitbox and per-type multipliers, crit, global multipliers, HP subtraction (DAMAGE-R01..R09);
  single-damage-type MVP (default; pending DN-ENT-01); i-frames 60 without refresh (DN-ENT-04); negative projectile damage
  clamps at 0 (default; pending DN-SPELL-09). Material contact damage belongs to the entity (HAZ-R01..R03, DAMAGE-R11).
- Statuses: the minimal spell-applied set (wet, oiled, bloody, on fire, frozen, poisoned/toxic, electrocution stun) with fixed durations,
  no passive stains (default; pending DN-ENT-05); entering liquid clears On Fire (DAMAGE-R14); air in lungs 7 s and suffocation
  15 HP/s from `player.json`.
- Player constants live in `player.rs`, sourced from `player-stats.json`: gravity 350 px/s^2, walk 57 px/s, fly up 95 / down 85 /
  horizontal 52 px/s, `fly_time_max` **180 frames (3.0 s)**, ground refill 6/s, air refill 0.4/s after 38 airborne frames, -8 frames per
  fly press, jump buffer 2 frames, no fall damage (`falling_damages = 0`). `fly_time_max` is a task-config override recorded in the task
  version. Aim and Formation geometry use `libm` or tables (DET-R06).
- Enemies from `enemies.json`: initial three are Hämis (`longleg`), Hurtta (`zombie`), Haulikkohiisi (`shotgunner`); Snipuhiisi and
  Stendari follow; no mutation or breeding (default; pending DN-ENT-07, DN-BEN-09). Factions fixed.
- `Input = { control: ControlState (held; `jump` edge-triggered inside the core), oneshots: Vec<OneShot> }` (ACT-R02, ACT-R03).

### 3.5 World-free wand evaluator
- `tasks/` holds an analytic evaluator over `CastOutcome` used for the `wand_dps_optimization` reference search (exhaustive for
  P <= 8 and capacity <= 6, 28,961 ordered subsets; fixed offline budget otherwise). The reference never leaves the harness (ANTI-R04).

## 4. Benchmark (KB: benchmark.md)

- Process: `noita_bench` speaks JSON Lines on stdin/stdout, `id` echoed, stderr for logs (PROTO-R01). Messages: `hello`, `list_tasks`,
  `info{what}`, `reset`, `step`, `observe`, `metrics`, `replay`, `close`; `save_state`, `load_state`, `debug` exist only with `--dev` and
  invalidate a run (ANTI-R03). Error codes `INVALID_ACTION, BAD_TASK, EPISODE_OVER, DEV_ONLY, PROTOCOL, LIMIT` (benchmark-design §2.2).
  `noita_bench verify run.jsonl` re-executes a log and reports `first_divergence` (ANTI-R01).
- `step{frames 1..600, actions, oneshot}`: `actions` has length 1 or `frames`; `max_frames_per_decision` (default 120) and
  `decision_limit` are enforced engine-side; an invalid action returns `ok:false`, advances no frame, counts as a decision and is echoed in
  the next observation's events (ACT-R01, ACT-R04, ACT-R05, ANTI-R07). `wait` is capped; it never skips an episode.
- Actions: held control `move, jump, fly, aim, fire, kick, interact, down`; one-shots `swap_wand, edit_wand{wand, spells[]}, drop_spell,
  pickup, wait`. The fire action is `fire`, not `cast`. Aim is signed degrees, integer in text mode and logged in the header (default;
  pending user decision DN-BEN-01). `edit_wand` obeys `wand_edit` policy (`anywhere | at_rest_zones | locked`), `max_wand_edits` default
  5, refused mid-cast (ACT-R03). RL space `MultiDiscrete([3,2,2,24,2,2,2,5])`, frame skip 4; sticky actions live in the client
  (default; pending DN-BEN-06).
- Observations: LLM text with priority down-sampling, default 4 px/char, `near` 1 px/char inset on for digging and aiming tasks (default;
  pending DN-BEN-03), fixed legend per `content_hash`, entities sorted by distance and capped at 16, goal never hidden, last 32 events,
  spell numbers = wand-editor numbers (OBS-R01..R06). RL: base64 arrays with shape/dtype/codec, never JSON number lists; the `grid`
  material channel is a `u8` observation class from a fixed legend (<= 254 classes), not the `u16` simulation id (OBS-R07, DN-BEN-10
  default; pending). Aiming and digging tasks need features >= 8 px or the `near` inset.
- Scoring: score in [0,1], monotone running maximum, cannot rise by dying; `terminated` is distinct from `truncated`; no time bonus
  (SCORE-R01..R05). **`Task` is stateful**: `setup(seed) -> Game`, `limits() -> {frame, decision}`, `wand_edit_policy`,
  `on_step(&Game, &[Event]) -> StepOutcome` (updates the running maximum), `score()`. A pure `score(&Game)` is not enough.
- Suite v1 (frozen list, DN-DRIFT-09): `dig_to_depth`, `cross_lava_pool`, `extinguish_fire`, `kill_targets`, `survive_N_seconds`,
  `wand_dps_optimization`, `reach_portal`, `chain_reaction`; stretch `lava_crust_bridge` (was `obsidian_bridge`; no obsidian exists),
  `collect_gold`. Each task declares its own world size (width 512, height per task; `dig_to_depth` D = 1024 needs about 1,152 px
  or an active window) and its geometry is recomputed from the player kinematics in 3.4 and validated by a scripted baseline before the
  task version is frozen. `extinguish_fire` is defined by burning-cell count with flooding or air starvation as the intended solutions
  (FIRE-R08; review decision 2); lava damage uses vanilla values (HAZ-R02).
- Seeds, versions, anti-cheat: `episode_seed = blake3(task_id || task_version || seed_index)`, public 0-19, hidden 20-39, raw u64 marked
  non-leaderboard (SEED-R01..R03); `protocol_version`, `engine_version`, `content_hash`, `task@N`, `suite-vX` (VER-R01..R06); `replay` and
  the run header also carry obs mode, assists, `wand_edit` policy, frame skip (ANTI-R05); header and `metrics.json` are written from
  the first version; golden hashes per `task@N`; a change to a golden hash is at least an engine minor bump (VER-R02).
- Python client (stdlib only): spawn, `reset/step/observe`, context manager, header writer; Gymnasium adapter optional and external.

## 5. Frontend and world generation (KB pages `frontend.md`, `worldgen.md` are NOT yet written; write them first)

### 5.1 `noita_game`
- Fills a camera-sized RGBA buffer (about 427 x 242 cells, 404 KB) directly from `World` using the palette, uploads it with
  `Texture2D::update`, draws with nearest filtering at integer zoom; view size comes from the camera, not from a bench window.
- Input maps to `ControlState`/`OneShot`; a 60 Hz accumulator decouples simulation from rendering.
- UI is a hand-rolled immediate-mode widget set (`macroquad::ui` has no drag and drop): click a spell to pick it up, click a slot to
  place it; `egui-macroquad` is not used (default; pending user decision DN-FE-01). Defaults for fonts, windowing: DN-FE-02.

### 5.2 `noita_core::worldgen`
- One global seed; fBm built from an **integer value-noise lattice keyed by world coordinates** (`hash(seed, ix, iy)`), so chunk borders
  have no seams and no float is needed. Chunk-local generation is a scheduling unit only; no chunk seeds the noise. Seed derivation
  follows DET-R04 (default; pending user decision DN-WORLD-01).
- Layered strata, caves, liquid pools, veins, rest rooms from the approved material set only (DN-MAT-01, DN-WORLD-03); fixed 2048x1536
  world, no streaming (default; pending DN-WORLD-04, DN-WORLD-02). Benchmark arenas are hand-authored or verified solvable by a ray or
  BFS test in the generator.

## 6. Determinism and testing policy
- Contract: bit-identical given `(engine_version, content_hash, task@version, seed, action_log)` for any thread count (DET-R01, DET-R08).
  No wall clock, no `HashMap`/`HashSet` iteration, no thread RNG, monotone entity ids (DET-R05).
- Floats: cell rules integer-only; particles Q16.16; entity and projectile `f32` limited to `+ - * / sqrt`, no FMA, no fast-math;
  `sin/cos/exp/powf` only through `libm` or tables; clippy `disallowed_methods` bans `f32::sin/cos/exp/powf` (SIM-R71, DET-R06; default;
  pending user decision DN-SIM-13). Golden hashes on macOS arm64 now; Linux x86_64 check is a later CI item (DET-R07, UNVERIFIED).
- Dependencies: `blake3` allowed for `content_hash`, `episode_seed`, state hash (licence check pending); `rand` is not used in `sim`.
- Determinism tests (SIM-T31..T35): 1/2/3/8/16 threads, random pass-order permutation, dirty rects on vs all-dirty, snapshot restore at
  frame k, random-soup fuzz, replay, and "an extra draw in `spells` leaves `worldgen` identical".
- Test-first (global rule): KB vectors are the tests (SIM-T01..T36, MV-01..MV-23, KV-01..KV-15, TV-D/S/B, corrected casting fixtures); every
  test cites its rule ID; probabilistic rules are seeded frequency tests (10,000 trials, 4 sigma). Target >= 80% line coverage of
  `noita_core` logic modules.

## 7. Trade-offs recorded
- Tile storage (32x32) with a safe window split instead of one flat Vec behind `unsafe`: costs indirection, buys memory safety; flat
  array is a measured fallback (SIM-R24).
- Fixed-size world (2048x1536 game, per-task benchmark worlds) instead of streaming; streaming can replace storage behind `World`.
- No Box2D in MVP; Bomb and Dynamite are ballistic; hooks kept (SIM-R86). `u16` material ids, all 466 materials loaded, MVP-40 enabled.
- 6-byte cell with no padding (same footprint as the padded 5-byte draft) holds lifetime and fuel without a temperature or parity channel.
- Pure casting engine plus a handler registry instead of an enum per spell id; costs a context struct, buys world-free tests and search.
