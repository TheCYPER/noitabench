# Cross-Module Contracts (v0, revision 2026-10-30a)

> Shared by every child task of `.trellis/tasks/10-16-noita-cogbench/`. Several sessions build the sim core, the world generator and the web viewer **in parallel**; these contracts are what lets their pieces fit. Change a contract only by editing this file in the same PR as the code, and bump its version string.

## 1. Repository layout

```
crates/
  sim/          Rust crate `cogbench-sim`: cell grid, materials, reactions, fire, explosions, recording writer
  game/         Rust crate `cogbench-game`: spells and wand casting (week 2 A3); player, enemies, items, potions and statuses, recipes (via `crates/rules`)
  py/           Rust crate `cogbench-py`: PyO3 bindings, built by maturin into the Python module `noitabench_core`
python/
  noitabench/   Python package: env wrapper, worldgen tools, harness, eval, server (`python -m noitabench ...`)
  tests/        pytest
content/        data files read by Rust and Python (sections 2–4)
web/            static viewer and play client (no build step required to open; see frontend spec)
runs/           recordings (git-ignored)
previews/       world preview images (git-ignored)
```

A cargo workspace sits at the repo root (`Cargo.toml` with `members = ["crates/*"]`). Python packaging uses a root `pyproject.toml` with maturin (`module-name = "noitabench_core"`, `python-source = "python"`).

## 2. Materials: `content/materials.json` (`cogbench-materials/0`)

- `materials[i].index` is the **u8 cell value** used everywhere: in the grid, in recordings, in observations. Never reorder or reuse an index; only append.
- Fields: `key`, `name_zh`, `name_en`, `noita_id`, `kind` (`air|gas|fire|liquid|powder|static`), `family`, `color` (`#RRGGBB`, the render colour; per-cell shading may vary brightness by up to ±12 %), physical numbers (`density`, `hp`, `durability`, `fuel_frames`, `autoignition`, `fire_temperature`, `requires_oxygen`, `lifetime_frames`, `liquid_gravity`, `viscosity`, `contact_damage_per_px_frame`), `tags`, `drink_effect`.
- Index 0 is `air`.
- Optional `explosion` object `{radius, ray_energy, max_durability, fire_percent}` (integers; radius 1..512, ray_energy ≥ 1, max_durability 0..255, fire_percent 0..100). A burning cell of such a material detonates with these numbers when its fuel runs out (`FIRE-R10`), and a blast sets off other such cells beside the crater. Only allowed on burnable materials. Today only `gunpowder` has one (8 / 400000 / 10 / 25). Additive: the format string stays `cogbench-materials/0` (revision 2026-10-26c).
- Indices 22–33 (revision 2026-10-27b, appended): `metal` (static, durability 15, not corrodible or burnable; the alchemy bowl), `gold_dust`, `bone_dust`, `fungus_powder` (powders), `slime` (liquid), and the secret potions `potion_invulnerable`, `potion_mana_regen`, `potion_crit`, `potion_berserk`, `potion_levitation`, `potion_invisible`, `potion_fireproof`. Tag `ingredient` marks the 12 recipe materials (water, blood, oil, whiskey, toxic_sludge, sand, coal, gunpowder, gold_dust, bone_dust, fungus_powder, slime). Tag `secret_potion` marks the 8 potions (those 7 plus `potion_lively`) that exist only as a recipe product and are never placed in the world. 34 materials in all.

## 3. Reactions: `content/reactions.json` (`cogbench-reactions/0`)

- Rows `{id, a, b, out_a, out_b, probability, source}`. `a`/`b` are material keys, `[tag]` (any material with that tag) or `@burning` (any burning cell). An output written as `[tag]` keeps the matched input material; `@extinguish` keeps the material and clears its burning state.
- `r04` is `acid + [corrodible] -> flammable_gas + air`: the acid cell is consumed and the corroded cell disappears, so a given amount of acid dissolves a bounded number of cells (deviation from `xml_052`, see `v1-scope.md` §5; revision 2026-10-26c).
- This file is the table every world runs, for every rule seed (CP2, revision 2026-10-27b). Recipes are not rows and are never listed here.

## 4. World grid: `content/biome_map.json` and generated worlds

- The world generator outputs a **world file pair**:
  - `<name>.png`: 8-bit **indexed** PNG, width × height = world size in cells, pixel value = material index (section 2). The PNG palette is filled from `materials.json` colours so the file is viewable as-is.
  - `<name>.json`: `{format: "cogbench-world/0", seed, rule_seed, width, height, biome_cell_size, biome_map: [[biome_key, ...], ...], markers: [{type, x, y, ...}]}`. Marker `type` ∈ `spawn_player`, `spawn_enemy` (`enemy` key), `item` (`item` key), `encounter` (`encounter_id`, `variant`, `trigger: {x, y, w, h}`, `must_pass`), `rest_area`, `seal`, `edit_station` (revision 2026-10-27b), `alchemy_bowl` (revision 2026-10-27c).
- Marker details (revision 2026-10-26b, additive):
  - `spawn_enemy.enemy` ∈ `longleg`, `shotgunner`, `firemage_weak`.
  - `item.item` ∈ `potion_heal`, `potion_mana`, `potion_haste`, `spell`, `wand`, `bottle`, `barrel_gunpowder`, `barrel_acid`, `barrel_oil`; a `bottle` carries `contents` (a material key); a barrel carries no `contents`; items may carry `tier`. A barrel marker `(x, y)` is a free cell standing on a floor cell with at least 10 free cells above it (revision 2026-10-26d).
  - Acid never appears as a grid material or as bottle contents in generated worlds; it only exists inside `barrel_acid` (and from the `MATERIAL_ACID` spell, or brick vats in encounter scenes).
  - Biome key `workshop` (废弃工坊) is layer 3 left (it replaced `acid_lake`). `rest_area` is a small brick hall (about 264 × 56) whose healing pool is `potion_heal` cells sunk into the floor.
  - World is at rest at frame 0 (the sim's own movement rules): a powder or liquid cell is at rest only if none of the cells below, lower-left and lower-right is air, gas, fire or a lighter liquid; a liquid also needs no air, gas or fire beside it. Pools keep one cell from other liquids, gas pockets keep 4 cells from lava. Lava and sand hazard pockets are sealed in ground and rock, and their crust differs from at least one neighbouring floor material (the cue). Enforced by `worldgen/rest.py`, `settle.py` and the post-generation checks.
  - `encounter.must_pass` is a JSON boolean; encounters may also carry `placeholder`, `layer`, `biome`.
  - `seal` carries `room: {x, y, w, h}`; `rest_area` carries `index`.
- Encounter scenes in the world JSON (revisions 2026-10-27a and b, additive):
  - There is no perturbation strength (CP2, revision 2026-10-27b). The reaction table is the original one for every seed; `rule_seed` only seeds the potion recipes in the engine, and slot liquids come from the original table (the same for every rule seed). Older world files may carry a top-level `strength`; readers ignore it.
  - `edit_station {x, y, w, h}` marker: the wand-editing station of a scene, the front hall above the seal plug (E06 region `edit_station`; moves and mirrors with the scene). `edit_wand` is allowed only inside `rest_area` and `edit_station` boxes (enforced by the agent layer).
  - Must-pass scenes are true chokepoints for a player who digs but cannot break brick (durability 14). Each must-pass band scene has a brick seam: `bands.seam` (4) rows across the whole middle biome at the height of the scene's `anchor_y`, with a hole exactly as wide as the scene footprint and inside its rows. The six side biomes are wrapped in a brick shell of the same thickness with their single gate cut through it, and the 3-cell world border is not overwritten where a seam or shell already put brick (elsewhere, e.g. in rest, start and seal rows, it stays rock). A route of free or diggable cells from the spawn to the seal front exists only through each scene's footprint; E06 is cut by its brick plug. The generator writes `meta.seams` (`[{layer, encounter_id, y, thick, hole: [x0, x1), added}]`), `meta.seam_brick` and `meta.shell_brick`.
  - An `encounter` marker that carries a scene also has `placeholder: false`, `variant`, `mirror` (bool), `params` (slot letter → material key), `footprint {x, y, w, h}` and `regions {name: {x, y, w, h}}`; `trigger` equals the footprint unless the definition says otherwise. An empty slot carries `placeholder: true`.
  - `encounter.must_pass` is true only for a chokepoint of the main path; a must-pass scene placed as an optional encounter in a side biome is `false`.
  - `seal` is `{x, y, w, h, room}`: `x, y, w, h` is the brick plug the breaker has to open (E06 `regions.plug`), `room` the sealed room beneath it.
  - Nothing is deeper than the plug (revision 2026-10-28c): from the plug's top row (`seal.y`) down to the world's last row, across the whole width and the 3-cell border included, every cell is brick except the vault room's air (generator 0.6.2, `scenes.brick_deep`; `meta.seal_brick` counts the cells that became brick, 59,352 for every seed checked). Post-generation check (`checks._check_seal`): the 8-connected area of free-or-diggable cells holding the spawn contains no cell at y ≥ `seal.y` (stats `seal_deep_cells` = 0, `deepest_reach_y` < `seal.y`); control: with the plug forced passable the vault room is reached and nothing but the plug and the room lies deeper than the plug's top edge (`seal_opens`, `seal_behind_plug` = 0). Depth below the plug counts only inside `seal.room` (§19).
  - Item markers of a scene may carry `role` and `encounter_id`. Roles: `reward`, `exhibit`, `sample`, `container`, `solvent`, `breaker`, and (revision 2026-10-28e) `decoy` (the wrong one beside the right one: E05, E21) and `remedy` (E21's healing potion, E24's bottle of water). A scene may place a `potion_heal` item marker; the entity's kind is `potion_heal`, not `bottle`. `role: "breaker"` marks a part of the seal key: the `BOMB` spell (E02) and the `EXPLOSIVE_PROJECTILE` spell (E12). Layer 3's must-pass scenes come in a random order except that E12 (`layers[2].last` in `biome_map.json`) is always the deepest, so the key is complete only after every other must-pass scene (post-generation check `key_order`, generator 0.6.4, stat `key_last`: fails a world where another must-pass band lies below E12, its modifier lies outside E12, or the BOMB lies at or below E12's top edge). A world holds exactly one role-marked item of each breaker spell (random spell pickups, random wands and E18's reward may hold more copies); each is reachable on foot without digging, meaning a walkable cell within the 14-cell pickup radius (an item inside a dig-zone scene with that scene's own zone left undug); and the best combination of the world's breaker spells that fits the starter spark wand (capacity 3, mana_max 100, modifier first) must reach the plug's brick durability (14). Spawned items settle up to about 6 cells from their marker, so readers match by item kind (and `spell` / `contents`) and nearest distance.
  - A `bottle` with no `contents` is an empty bottle (E07's containers).
  - `role`, `params`, `regions` and `encounter_id` are harness and tooling fields: they name the solution and are never shown to an agent.
  - Acid appears in the grid only inside the brick vats of scenes whose definition sets `allow_acid` (E07, E16) and in `barrel_acid`. Scene enemies stand on a floor with their `entities.json` `collision.h` free above; barrels follow the 10-cell rule.
- Closed scenes (revisions 2026-10-28b and d, generator 0.6.3): the chokepoint also holds inside a footprint. Every must-pass scene that is not a dig zone (E02, E07, E16, E22, E23; E06 on its art only) is a closed box: its outer wall (normally 4 cells, 3 at the top; E23's far bank 2, the E06 hall's top 2) is brick except at its doors, the rows just above and below each sealed solution region are brick (no grazing through the roof or bed of a river, trough or pool), and brick bulkheads wall off the rock round each obstacle (the roof over a river, the bed under a trough, the block between two roads), so a digger who cannot break brick or metal gets from the top door to the exit only through the scene's solution regions: `river_gate` (E02), `acid_gate` then `lava_gate` (E07), `crossing` (E16), `short_gate` or the existing `long_route` (E22), `pool_gate` (E23), the existing `plug` (E06). Tooling fields, never shown to an agent.
- Hazard clearance (revision 2026-10-27e): the generator records `meta.clearance = {reach: [1, 1, 7, 2], blast_radius: 80, lanes: [{encounter_id, layer, footprint: {x, y, w, h}, tunnels: [{x, y, w, h}]}]}`. `reach` is how far the player's 6 × 16 hit box reaches left, right, up and down beyond the 4 × 7 collision box; `blast_radius` is the seal key's explosion radius (75, from `spells.json`) plus 5. One lane per placed must-pass scene: a band scene lists its two door tunnels, E06 the gate shaft above it and that shaft's link. Tooling field, never shown to an agent; worlds written before generator 0.6.0 have none (and fail the check). Guarantee: outside a scene's own footprint no lava, acid or fire cell lies in the hit box of any collision-box position that fits on non-static cells and overlaps the scene's footprint or tunnels (contact damage and ignition go through walls), and none lies within 80 cells of the hall above the plug (the E06 footprint rows above the plug, wherever in the hall the bomb comes to rest; generator 0.6.1, `clearance.Blast.of_seal`), so the key blast cannot loose lava into the hall or the sealed room. Toxic sludge and flammable gas are not covered. Enforced by `worldgen/clearance.py` (lava pools, pockets and scenes with lava or acid keep out of the zones) and the post-generation check `worldgen/clearance_checks.py`.
- Alchemy and supplies (revision 2026-10-27c):
  - `alchemy_bowl {x, y, w, h, place}` is the open interior of a metal bowl (interior 20 × 10, walls and bottom 2 thick, rim level with the floor; the outer box is the interior grown by 2 left, right and below; rim row = `y`). `place` is `rest` (in a rest hall's floor: centre column inside the `rest_area` box, `y` = the box's bottom edge) or `cave`. Tooling and evaluator marker, never shown to an agent (the agent sees `metal` terrain).
  - A `bottle` marker's `contents` may be any `ingredient` material, powders included. Worlds never contain a `secret_potion` cell or bottle. The rest hall is about 352 × 56.
  - Generated-world guarantees: each of the 12 ingredients has ≥ 40 cells within 6 cells of the walkable area and at least one reachable full bottle (8 of them in layer 1, all 12 by layer 2); ≥ 6 empty bottles up to the first rest area and ≥ 10 in all; one bowl per rest hall plus the cave bowls the biome files ask for (3 today); metal only in bowls and scene footprints. `meta.deposits` lists `{material, form, shape, biome, x, y, cells}` (`shape` heap, basin or pit) as placed, before settling (about a quarter of heaps slide elsewhere in the same biome; the 40-cell and bottle checks still guarantee obtainability). No secret potion appears at frame 0 for any rule seed: the post-generation check `worldgen/mixing.py` re-runs the engine's mixing rule for every ingredient triple (skipping pairs that react) and rejects a world where three ingredients touch.
- Optional top-level `meta` object written by the generator: `generator`, `version`, `attempt`, check statistics, and `main_path` (a polyline, list of `[x, y]`) used by previews and evaluation.
- Readers ignore unknown fields everywhere (no `deny_unknown_fields`).
- Coordinates: cells, origin top-left, y grows downward. Every `{x, y, w, h}` box (triggers, entities, rooms) uses the top-left corner.
- The sim loads a world with `Env.from_world(png_path, json_path)` (section 6).

## 5. Recordings: `runs/<run_id>/` (`cogbench-rec/0`)

Written by the sim (Rust), read by the web viewer. All integers little-endian.

| File | Content | Required |
|---|---|---|
| `meta.json` | `{format: "cogbench-rec/0", run_id, created, world: {width, height}, materials_format, seed, rule_seed, frame_stride, notes}`; optional `rect`, `frame_count`, `first_frame`, `last_frame`. `seed`/`rule_seed` are u64: readers that use doubles must keep the exact digits | yes |
| `frames.bin` | Sequence of frame records (below) | yes |
| `entities.jsonl` | One line per recorded frame (and the final frame): `{frame, entities: [{id, kind, x, y, w, h, hp, hp_max, detail?, status?}]}`; `x, y` is the top-left of the visible hit box; `kind` ∈ `player`, enemy keys, `wand`, `spell`, `bottle`, `potion_*`, `barrel_*`, `bomb`, `projectile` | no |
| `events.jsonl` | One line per event: `{frame, type, ...}` (e.g. `reaction` with `x, y, bx, by`; `explosion` with `x, y, radius`; `ignite`; `extinguish`; `overflow` when the event buffer dropped events; later `damage`, `death`, `pickup`) | no |
| `decisions.jsonl` | One line per decision point (revision 2026-10-27b): `{frame, index, stop_reason, command, observation_digest}` plus optional `result` (the decision's stop object), `frames` (frames it advanced), `ok` (no command failed). `index` is the budget counter after the decision (`session.decisions`; an `inspect` costs one more and a notes-only decision 0, so `index` can skip or repeat; the number the player was shown, "Decision N", is `index - cost + 1`; readers use `cost`, and files without it use `index`); `frame` is the frame at which the agent was asked; `stop_reason` is what the agent was shown; `command` is the list of checked `{name, args}` or, if the request could not be read, the request as sent; `observation_digest` is the first 16 hex characters of the SHA-256 of the canonical JSON (sorted keys, compact, UTF-8) of the answer shown. No wall-clock values | no |

Frame record: `u32 frame | u16 x0 | u16 y0 | u16 w | u16 h | u8 codec | u32 nbytes | nbytes of payload` (17-byte header). Frame numbers never decrease; consecutive records with the same `frame` form one step (several rectangles of the same frame). `codec` 0 = raw, 1 = zlib (deflate with zlib header). Decompressed payload = `w*h` bytes of material indices, row-major, for the rectangle `(x0, y0, w, h)` of the world. A full-world frame has `x0 = y0 = 0`. Burning state is not in v0 frames; it arrives as `events.jsonl` or a later format version.

The viewer must ignore unknown fields and missing optional files.

## 6. Python API of the sim (week 1 surface, `noitabench_core`)

```python
env = noitabench_core.Env(width, height, seed)          # empty world (air)
env = noitabench_core.Env.from_world(png_path, json_path, seed)
env.step_frames(n)                                       # advance n frames at 60 Hz
env.paint(x, y, radius, material_key)                    # disc of a material, for tests and demos
env.grid() -> bytes                                      # width*height material indices
env.cell(x, y) -> dict                                   # {material, burning, lifetime}
env.snapshot() -> bytes ; env.restore(blob)              # full state, bit-exact
env.events() -> list[dict]                               # events since the last call
env.start_recording(dir, frame_stride, rect=None) ; env.stop_recording()
```

Grid queries (revision 2026-10-26c), also on the `noitabench.env.Env` wrapper:

```python
env.overlap(x, y, w, h) -> {inside, outside, burning, kinds: {name: n}, materials: {key: n}}
env.raycast(x0, y0, x1, y1, mask="blocking", *, ignore=None) -> {x, y, material, kind, last_free, step, steps} | None
env.sweep_box(x, y, w, h, dx, dy, mask="blocking", *, step_up=0, ignore=None) -> {x, y, blocked_x, blocked_y, climbed}
env.contact_damage(x, y, w, h, *, min_cells=4, max_cells=85) -> {raw, parts: [{material, cells, counted, damage}]}
```

`mask` is `any`, `surfaces`, `surfaces_and_liquids`, `platforms`, `blocking`, or a list of kinds. Cells outside the world stop every mask and report material `"boundary"`. Numeric arguments are signed 32-bit (`ValueError` otherwise). `contact_damage` is raw internal damage per frame (× 25 for display); the 4-cell minimum and 85-cell cap apply per material (`HAZ-R01`). The same queries are public Rust API in `cogbench_sim::query` for `crates/game`.

Later weeks add commands, observations and the harness; they extend this class, they do not rename these methods.

Game API (revision 2026-10-26e), class `noitabench_core.Game` and wrapper `noitabench.game.Game`:

```python
g = noitabench_core.Game(w, h, seed)                                   # empty world
g = noitabench_core.Game.from_world(png, json, seed=None, rule_seed=None, reactions_json=None)
g.step(frames=1, controls=None)     # one dict held for all frames, or a list with one dict per frame
g.player() -> dict | None           # x y w h (collision box, top-left), hit, vx vy, hp hp_max (displayed), dead, facing,
                                    # on_ground, fly, breath (0..1), invincible, aim, active_wand, active_bottle,
                                    # wands[{id, stats, slots[{spell, uses}|None], always_cast, mana, mana_max, cooldown}],
                                    # spells[{spell, uses}], bottles[{material, amount}], statuses{name: frames}
g.entities() -> list[dict]          # id kind x y w h hp hp_max vx vy detail statuses (hp displayed, box top-left)
g.events(); g.markers(); g.snapshot() / g.restore(blob); g.state_hash()
g.start_recording(dir, stride, ...) / g.stop_recording()      # also writes entities.jsonl
g.spawn_player / spawn_enemy / spawn_item / give_wand / give_spell / give_bottle / edit_wand / blast
g.paint / fill_rect / ignite / explode / grid / cell / overlap / raycast / sweep_box / contact_damage / material_keys
```

Revision 2026-10-27b: `noitabench_core.rules()` (base-table queries `transforms, reactions_for, lava_solidifiers, extinguishers, water_family_extinguishes, acid_dissolves, ignites, check_invariants`, plus `content_hash`, `reactions_json`, `recipes(rule_seed)`) and `noitabench_core.recipes(rule_seed) -> [{potion, inputs: [a, b, c]}]`. `Env(...)` and `Game(...)` take `rule_seed=None, recipes=None`; `from_world(..., recipes=None)` defaults to the recipes of the file's rule seed, `[]` means none; empty worlds have no recipes unless given.

Bottles and drop (revision 2026-10-27c): `player()["bottles"]` is `[{material, amount, contents: [{material, amount}]}]` (`material` = the largest share or `None` when empty; `amount` = total); `entities()` bottle dicts carry `contents`, ground wand dicts carry `wand` (same shape as `player()["wands"][i]`); `give_bottle(contents=[...])`, `spawn_item("bottle", contents=[...])`; `end_bottle_action()` writes pending bottle summary events (call it when a plan ends on the last frame of a tick); `on_ground` is the grid state at the end of the frame.

Controls dict keys: `drop` (`{"wand": i}` / `{"spell": i}` / `{"bottle": i}`, acts when the value appears or changes; the item lands beside the player on the facing side, else the other side, else on the player; a wand keeps its id, RNG, mana and slots and does not recharge on the ground; a bottle keeps its mixture), `move` (-1/0/1), `jump fly fire kick interact drink pour fill throw` (bool), `aim` (degrees, 0 = right, 90 = up), `select_wand`, `select_bottle`. Unknown keys raise `ValueError`. `jump`, `kick`, `interact`, `throw` and `fly`-in-air act on the press edge. `g.state_hash()` serializes the whole state (tests and debugging, not per frame).

Build notes (revision 2026-10-26b):
- `content/materials.json` and `content/reactions.json` are **embedded into the module at build time**; after editing them, rebuild. `Env(...)` and `Env.from_world(...)` also accept an optional `content_dir` to load another copy at runtime.
- Build the module into the project venv only: `env -u CONDA_PREFIX VIRTUAL_ENV=$PWD/.venv PATH=$PWD/.venv/bin:$PATH maturin develop --uv --release -m crates/py/Cargo.toml`. Running `maturin` without the venv variables can install into a global or conda Python.
- `python -m noitabench <command>` dispatches lazily: `demo` (sim), `world` (worldgen), later `serve`.

## 7. Reproducibility (every module)

- Same seed + same calls ⇒ identical `grid()`, `events()` and recordings. Tests assert this by hashing two runs.
- Single-threaded simulation. No `HashMap`/`HashSet` iteration in simulation code (`DET-R05`).
- Cell randomness is a stateless hash of `(seed, frame, pass, x, y)` (`SIM-R70`); other randomness uses named streams derived from the seed (`DET-R04`).
- Floating point only where `DET-R06` allows; no `fast-math`.

## 8. Spells: `content/spells.json` (`cogbench-spells/0`) — revision 2026-10-27a

- Generated, never hand-edited: `PYTHONPATH=python .venv/bin/python -m noitabench.content_tools.build_spells` (from `research/spells.json` plus the raw game XML; `--check` verifies the committed file is current). `crates/game` embeds it at build time (`SpellBook::embedded()`): rebuild after regenerating.
- Top level: `format`, `source`, `units`, `spells[]`. A spell's id is its index in `spells[]`; never reorder, only append. Keys are upper snake case (`LIGHT_BULLET`).
- Units: frames, px, px/s, degrees. Damage is **internal** (player max HP 4.0 = 100 displayed; observations multiply by 25), the same unit as `contact_damage_per_px_frame`.
- Spell fields: `key`, `name_en`, `name_zh`; `type` (`projectile|static_projectile|modifier|multicast|material`); `mana` (negative adds mana); `max_uses` (`null` = unlimited); `draw`; `trigger` (`null` or `{kind: collision|timer, timer_frames, payload_draws}`); `cast_delay`, `recharge`, `recoil`; `shot` deltas (`spread`, `speed_mul`, `damage`, `explosion_damage`, `explosion_radius`, `crit_chance`, `bounces`, `trail[{material, amount}]`, `effects[wet|oiled|on_fire]`, `explosion_durability`). `explosion_durability` (integer, 0 when absent) raises the max durability of the explosion of the projectile a modifier modifies; it is a cogbench extension not in Noita's data, written for every spell by `build_spells.py` from its `EXPLOSION_DURABILITY` table (`EXPLOSIVE_PROJECTILE` 3, all others 0).

## 15. Agent interface: `noitabench.agent` — revision 2026-10-27b

- Entry points: `AgentSession(game, config=SessionConfig(...), memory=None, recording_dir=None)` with `observe()`, `decide(request)`, `snapshot()` / `restore()`, `close()`, `interrupts`, `decisions`, `frame`, `over_reason`; `python -m noitabench agent play (--world-seed N [--rule-seed R] | --world-files PNG JSON) [--out DIR] ...`; `protocol.serve`; `tools.tool_schemas()` / `call_tool`; `mcp_adapter.tool_payload`. Only `agent/engine.py` touches the `Game`.
- Time model B (`tick-design.md` §4): a tick is 10 frames; a decision is a list of commands (text such as `aim(target=4); fire(until=target_dead)`, dicts, or one tool call) run in order; time-taking commands run until done, interrupted, or the decision's 300-frame budget is used up (the cap is per decision); every decision point is on a tick boundary; nothing advances between decisions. `max_decisions` (default 1000) ends the run with `over: "decision_limit"`; death gives `over: "dead"`.
- Commands, timing and arguments are defined in `agent/spec.py` and exposed as tool schemas. No game time: `aim`, `edit_wand`, `inspect`, memory ops. One tick: `kick`, `swap_wand`, `pickup`, `throw`, `drop`. Until done: `move`, `walk_to`, `jump`, `fly`, `fire`, `wait`, `drink`, `pour`, `fill`. `until` is any-of over `ticks` (1–30), `distance`, `x`, `blocked`, `edge`, `landed`, `hp_below`, `target_dead`, `mana_empty`, `event`. Invalid commands answer `{ok: false, code, message}`, take no time and count as a decision. `edit_wand` works only when the centre of the player's collision box is inside a `rest_area` or `edit_station` box (otherwise `not_here`). `drop` takes one tick (wand, spell or bottle index; codes `no_such_wand`, `no_such_spell`, `no_such_bottle`). A decision holds at most 4 commands (more: `too_many_commands`, cost 1, no time). Cost against `max_decisions`: 1 for the non-`inspect`, non-notes commands (if any) plus 1 per `inspect`; notes commands (`memory_*`) are free, so a decision of only notes costs 0, otherwise the minimum is 1; `decisions.jsonl` records `cost`. Walking (revision 2026-10-28a, after the CP3 human play): `move` / `walk_to` never stop for a drop — the player walks off a ledge and falls (no fall damage), holding the direction in the air; `walk_to` brakes at its column also in the air and reports `reached` only when the player stands or swims. `until=edge` (`move` / `walk_to` only, `bad_argument` elsewhere) stops with the front foot on the ground before a drop deeper than 8 cells (`completed`, detail `edge`, "There is a drop ahead."; 0 frames when already at the edge). A wall is felt, not predicted: the key held for `STALL_FRAMES` = 10 frames with the player's cell unchanged (ledges up to 4 cells are climbed); a walk already against a wall ends after 10 frames as `interrupted` / `blocked`, or `completed` / `blocked` with the interrupt off or `until=blocked` ("A wall is in the way."); the `blocked` interrupt and `until=blocked` are for walls only; `landed` for walks waits for a touch-down after leaving the ground. `none` works as a `jump`/`fly` direction.
- Interrupts: `damage`, `new_enemy` (once per creature), `status_change` (new status), `blocked` on by default; `fell_in_liquid`, `hp_low`, `new_material` off, switched on through `session.interrupts` (harness hooks). A command that completes on the same tick wins over an interrupt.
- Answer: `{protocol: "cogbench-agent/0", decision, frame, seconds, decisions_left, over, stop{reason, detail?, message?, ticks, frames}, results[{command, ok, result? | stop? | code + message}], events[{tick, frame, type, ..., text}], events_omitted, observation{state?, map?, screenshot?}}`. Stop reasons: `start`, `completed`, `interrupted`, `time_limit`, `invalid`, `dead`, `over`. Channels switch with `ViewConfig(text, ascii, screenshot)` (default text and ASCII on). The ASCII map is 64 × 32 characters at 4 × 4 cells; the screenshot a 256 × 192 PNG in material colours; the legend names materials and creatures only, never properties. Events are whitelisted (`vocab.EVENT_TYPES`), merged, capped at 16, and given as offsets from the player. One range (revision 2026-10-27c): entities, `inspect(x, y)`, `inspect(entity)`, event positions and the `new_material` window use the ASCII map's extent (default ±128 × ±64), creatures and items also need a clear line of sight. `nearby` lists only `id, kind, x, y, w, h, dx, dy` (plus `hostile`, `aimed`); potions show as `bottle`; contents, potion identity, spell keys, HP and statuses come only from `inspect` (`inspect(entity=<bottle>)` returns `contents`, `amount`; on a ground wand, `wand`). `inspect` gives exact facts and never a material's properties or family. `stop.also` is also set on `completed` (an interrupt on the time-limit tick wins as `interrupted`). Damage events about other creatures carry no HP; their visible `status` events (e.g. on fire) are reported.
- Details (check of 2026-10-27): `stop` may also carry `also` (other interrupts on the same tick) and, for `invalid`, `code`; `AgentSession` takes `notes=` (the notes backend). A command that fails to read takes no time; one that fails while running (`no_such_bottle`, `nothing_in_reach`, ...) after earlier time-taking commands of the same decision leaves the time already spent. `stop.ticks` / `stop.frames` describe the last time-taking command; the decision's total is `frames` in `decisions.jsonl`. ## 21. Knowledge base and note claims: `noitabench.eval.knowledge` — revision 2026-10-28h

User decision (2026-10-28): a detailed knowledge base, generated from the data files, is the answer key for the agent's notes.
