# NoitaClone 计划汇报（2026-10-07）

**现状：** 调研、知识库和计划文档已经完成，代码还一行没写。等你看完这份汇报、确认或修改第 6 节里的机制选择之后，再开始实现。

---

## 1. 引擎选择：Rust + macroquad，不用 Godot，也不用 JS

- **不用 Godot。** 你的电脑上没装 Godot。更关键的是，像素物理每帧要更新几十万个像素，在 Godot 里也只能用原生扩展写，等于多背一个编辑器。做 benchmark 还要求无界面、可脚本化运行，一个 `cargo run` 就能跑起来最省事。
- **核心不用 JS。** JS 能做画面，但核心模拟要又快又"逐位确定"：同一个种子加同一串操作，必须得到完全一样的结果。Rust 在这两点上都更稳。
- **macroquad 是很薄的 Rust 游戏库。** 只负责开窗口、画图和读键盘鼠标，已在你的 Mac 上编译通过。核心不依赖任何画面库，以后想换 Godot、网页或 WASM 前端都可以直接接上。

## 3. 用大白话讲 Noita 的两个核心机制

### 3.1 像素物理

- **每个像素都是一种材料。** 世界就是一张巨大的像素网格。
- **材料按种类运动。** 岩石等静态材料不动。沙子等粉末往下掉、往两边滑、会堆成坡。水等液体往下流、往两边铺开，并且按密度分层，所以油会浮在水上。烟和蒸汽这类气体往上飘，过一段时间消散。
- **化学反应查表。** 两种材料相邻时，按概率变成别的材料。比如水碰到岩浆，变成蒸汽加岩石；酸会腐蚀大多数东西。
- **火是一种"燃烧状态"，不是单纯的材料。** 可燃物达到燃点就会烧起来，直到烧光或缺氧才停。按 Noita 的真实规则，水会被烧开，但浇不灭正在燃烧的东西。
- **爆炸是一圈射线。** 每条射线带着能量往外走，穿过每个像素都要付出该材料的"硬度"作为代价。所以同一颗炸弹在泥土里能炸出约 6 像素深，在岩石里只有约 1 像素。
- **只模拟有变化的区域。** 世界切成 64×64 的小块，没有变化的块直接休眠。这就是大世界还能跑得动的原因。

### 3.2 法杖和法术

Noita 的法杖本质上是一个**卡牌游戏**：

- **按顺序抽牌。** 法杖里的法术像一副牌，每次施法从左往右抽。
- **投射物法术**，比如火花弹、炸弹，会真正发射出一个东西，抽到它这一发就完成了。
- **修饰法术**，比如加伤害、加速、穿透，会改变"这一发"的属性，然后自动再抽下一张。
- **多重施法**，比如双重、三重，一次多抽几张，同时射出去。
- **触发法术**，比如"带触发的火花弹"，会把后面的法术打包成"载荷"，等它命中、计时到点或消失时再释放。复杂的连锁组合都靠它。
- **牌抽完就要充能，也就是换弹。** 每张牌都会给"施法延迟"和"充能时间"加减几帧，所以搭配会直接影响射速。
- **法力不够时跳过这张牌。** 有的法术还有使用次数限制。

这套规则已经对照游戏自己的法术脚本核实过，并写成了可直接实现的伪代码和测试向量。

## 4. 整体架构

| 部分 | 内容 |
|---|---|
| `noita_core` | 整个游戏本体，没有窗口：像素世界、材料与反应、法杖与法术、角色与敌人、地图生成、给 agent 的观测编码、benchmark 任务与计分 |
| `noita_bench` | 无界面程序，通过标准输入输出收发 JSON，附带 Python 客户端 |
| `noita_game` | macroquad 窗口，给人玩：画面、操作、HUD、法杖编辑器、调试工具 |

**所有游戏规则只写在 `noita_core` 里。** 这样人玩的版本和 agent 测的版本不可能出现分歧。

benchmark 的关键设计：

- **逐位确定。** 同一个种子加同一串操作，必须得到完全相同的结果。用 1 个线程还是 8 个线程跑，结果也完全一样。
- **防作弊。** 每一步都计算状态哈希，提交的操作记录可以重放校验，篡改会被发现。
- **两种观测。** 给大模型的是文字版：角色周围的字符地图、实体列表、法杖数值。给强化学习的是数组版：材料网格加数值向量。
- **第一版有 8 个任务。** 包括挖到指定深度、跨过岩浆池、灭火、击杀目标、走到传送门，以及"给定一堆法术，组装伤害最高的法杖"。

## 6. 需要你决定的机制

核心矛盾是**还原 Noita** 和**benchmark 简单可控**之间怎么取舍。每一条都已有推荐默认值，你只需要改你不同意的。

| # | 机制 | 推荐默认 | 另一种选择 | 对 benchmark 的影响 |
|---|---|---|---|---|
| 1 | 炸弹、炸药这类会滚的物体 | 简化成带引信、会弹跳的投射物 | 去掉；或以后接真正的刚体物理 | 确定性好、成本低，但滚动手感和 Noita 不同，也推不动箱子 |
| 2 | 灭火 | 还原 Noita：水浇不灭燃烧物，只能断燃料或断氧气 | 简化：水直接灭火 | 还原版更难也更有意思，但每个灭火任务都必须先证明有解 |
| 3 | 爆炸挖地 | 射线消耗能量，挖多深取决于材料 | 简单圆形挖坑 | 挖掘任务会考验 agent 对材料硬度的理解 |
| 4 | 爆炸和水花溅出的物质 | 先推到最近的空位，以后再做飞溅粒子 | 一开始就做完整粒子系统 | 基本不影响分数 |
| 5 | 化学规模 | 启用 40 种材料、39 条反应 | 全部 466 种、330 条 | 越多越丰富，但更慢、更难调平衡；每加一种，旧成绩就不能直接比较 |
| 6 | 液体、气体、反应的手感 | 用我们校准过的公式 | 无。Noita 的精确公式并不公开 | 只能做到像 Noita，做不到一模一样；任务按版本冻结 |
| 7 | 法术范围 | 分阶段：先 50 个，再 127 个纯数据法术，最后到约 300 个 | 一次做完 422 个 | 有 185 个法术需要专门写代码；任务里只会出现已实现的法术 |
| 8 | 法杖规则里来源没说清的细节 | 牌抽空就充能；任务用手工设计的 3 到 8 格法杖 | 随机生成法杖；最多 26 格 | 组装法杖任务能算出可复现的参考答案 |
| 9 | 穿透型投射物 | 支持，同一目标只打一次 | 命中即消失 | 前 50 个法术里就有闪电和穿透弹 |
| 10 | 伤害和状态 | 单一伤害类型；状态只由法术施加 | 完整多类型伤害；站在水里会自动变湿 | 简化版少了一些深度，但更好预测 |
| 11 | 移动手感 | 照搬 Noita 数值，悬浮 3 秒；瞄准取整数角度 | 缩短悬浮时间 | 任务地形会按这些数值设计 |
| 12 | 世界大小 | 游戏 2048×1536；benchmark 512 宽，高度按任务定，并验证有解 | 无限流式世界 | 每个任务都能证明可解 |
| 13 | 敌人和范围 | 8 种基础敌人，先做 3 种；没有天赋、商店、Boss | 加入天赋、商店、Boss | 随机事件少，便于复现 |

## 7. 最影响设计的几个问题

在细调第 6 节之前，下面几个关于你最终目标的问题，会比单条机制更影响整体设计：

1. **主要测哪类 agent？** 大模型 agent 走文字观测，每步慢、贵，适合短任务。强化学习 agent 要跑上百万步，适合数组观测。两者都要的话，任务长度和观测设计要两头兼顾。
2. **主要想测什么能力？** 物理和化学推理、空间导航、法杖组合优化、长程规划、实时操作，各自需要的机制深度不同。比如"组装法杖"任务最依赖第 7、8 条，"灭火"和"连锁反应"最依赖第 2、5、6 条。
3. **回合制还是实时？** 现在的设计是 agent 每一步可以停下来思考，世界不动，每步推进若干帧。这对大模型友好。如果你想测实时反应能力，需要另加一条实时赛道。
4. **还原度有多重要？** 如果目标是"像 Noita 的物理世界里的通用 agent 测试"，可以大胆简化。如果目标是"Noita 玩家觉得像 Noita"，第 1、2、6、10 条就应该偏向还原。

## 8. 主要风险

- **性能还没实测。** 所有速度数字都是估算，M1 第一件事就是测。
- **"手感"无法和 Noita 精确对齐。** 液体、气体、火的公式都是推测，只能对照游戏录像调。
- **法术太多。** 185 个法术需要逐个写代码，所以采用分阶段推进。
- **机制改得越晚越贵。** 规则一变，所有哈希和版本都要跟着变，所以第 6 节最好在 M1 之前定下来。
